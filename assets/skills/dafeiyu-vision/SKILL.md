# 大肥鱼识图：给 agent 的使用指南

大肥鱼（DeepSeek）没有视觉。这个插件把图片送出去"看"，再让大肥鱼基于回来的**文本**回答。
你（agent）要做的只有一件事：**调 `recognize_image`**，别假装自己看到了图。

## 1. 什么时候该调

| 情况 | 做法 |
|---|---|
| 用户给了图片文件路径（`C:\…\x.png`、`/tmp/a.jpg`） | `recognize_image({ image_path })` |
| 用户把图贴进聊天、你收到「【图片识别】」开头的文本 | **不要再调**，那是别人替你看过的结果，直接基于它答 |
| 用户只描述图（没路径、也没粘图） | 先问路径；别凭空编图片内容 |
| 同一张图要问多个问题 | 调用一次拿完整描述，之后基于那段描述逐条回答（重复调用很慢，网页版尤其慢） |

## 2. 三个工具

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `recognize_image` | 识图主入口：`{ image_path, prompt? }`，返回文本描述 | 常规使用 |
| `vision_guide` | 返回**本指南正文**（就是你正在看的这份） | 上下文里没有本 skill 时兜底；或想确认最新口径 |
| `vision_web_status` | 查网页版（豆包 / Gemini）登录态：`{ site?: 'doubao' \| 'gemini' \| 'both' }` | 识图报"没登录"时先查这个 |
| `vision_web_login` | 在用户机器上**弹出有头浏览器窗口**让用户登录：`{ site }` | 只有确认没登录、且用户人在电脑前时才用 |

`recognize_image` 的 `prompt` 是**这一次**的指令（例如"只把这页的报错代码抄出来"），
不传就用设置页里那份默认提示词（要结构化描述 + 逐字转录）。

## 3. 它背后可能走哪一路（你不用管，但要知道差别）

设置页「肥鱼识图」里有两个开关：

- **白嫖豆包**：开 = 走本机浏览器里已登录的**网页版**（不花 API key）；关 = 走外挂视觉模型 API。
- **识图模式**：
  - `单一`：只跑一路（开着白嫖就是网页版，关着就是 API）；
  - `复合`：两路**并行**都跑，结果按来源合并成 `【网页版豆包】…【外挂模型（…）】…`。

对你的影响只有"延迟"和"措辞"：

- API 那路几秒；网页版那路 **10~25 秒**（要等网页流式结束），所以工具 `timeoutMs` 给到 120 秒；
- 复合模式返回的是**两段带来源标注**的文本：回答用户时不要复述标签，把两边内容**合并成一份**；
- 两段说法冲突时（比如文字转录不一致），**明确告诉用户有分歧**，别自己挑一个当真。

## 4. 报错怎么读（别自己瞎猜）

| 报错里出现 | 真实原因 | 你该做什么 |
|---|---|---|
| `识图未开启` | 设置页总开关关着 | 告诉用户去「设置 → 肥鱼识图」打开开关（不用重启，工具侧实时读配置） |
| `还没配置 API Key` | 走的 API 那路但没 key | 要么填 key，要么建议打开「白嫖豆包」 |
| `没有登录` / `切不到项目` | 网页版没登录 / 项目名对不上 | 先 `vision_web_status`，需要时 `vision_web_login`（要人在电脑前） |
| `没有返回可读的回答` | 页面结构变了或站点侧出错（附截图路径） | 把截图路径和原因原样告诉用户，别重试三遍 |
| `图片太大` | > 20MB | 让用户压缩后再发 |
| `两路都失败` | 复合模式下两路都挂了 | 错误里带两边原因，分别转述 |

## 5. 限制（回答时别说满）

- 一次一张图；网页版那路会**真的在用户机器上开浏览器**，慢且会留会话记录；
- 偶发验证码：需要用户在弹出的窗口里点一下；
- 识图结果是**别人（另一个模型）的描述**，可能有错；关键事实（金额、合同条款、报错原文）建议二次确认。
